# Security Policy

## Overview

Dev-Trace is a collection of educational projects documenting the process of learning, experimenting with, and deepening an understanding of programming and computer systems.

Although these repositories are primarily intended for educational purposes, security-related issues may still arise in the source code, dependencies, documentation, or project configuration.

Responsible security research and disclosure are appreciated.

## Supported Versions

These projects are maintained as learning exercises rather than production software. Security fixes and updates are handled on a best-effort basis.

Unless explicitly stated otherwise, only the latest version available on the default branch is considered for security-related fixes.

Older commits, experimental implementations, and archived code may not receive security updates.

## Reporting a Vulnerability

**Please do not disclose suspected security vulnerabilities through public GitHub Issues, Discussions, or pull requests.**

To report a potential vulnerability, use GitHub's private vulnerability reporting feature.

To do so:

1. Open the repository on GitHub.
2. Navigate to the **Security** tab.
3. Look for **Report a vulnerability**.
4. Submit a private report containing the relevant details.

## What to Include in a Report

To help assess and understand the issue, please include as much of the following information as possible:

- **Description:** What is the suspected vulnerability?
- **Affected component:** Which file, function, dependency, or configuration is involved?
- **Impact:** What could happen if the issue were exploited?
- **Reproduction steps:** How can the issue be reproduced safely?
- **Evidence:** Relevant code snippets, logs, screenshots, or a minimal proof of concept, where appropriate.
- **Suggested mitigation:** Any proposed fix or workaround, if known.

Please avoid including passwords, access tokens, personal information, or other sensitive data in the report.

## Responsible Disclosure

Please allow the maintainer a reasonable opportunity to review and address a reported vulnerability before publicly disclosing technical details.

Please do not access, modify, or disrupt systems or data that you do not own or have explicit permission to test.

As these projects are primarily educational simulations, please distinguish between issues affecting the example code itself and issues affecting the simulator, development tools, or external systems.

## Scope and Limitations

Dev-Trace repositories are educational projects and are not intended to provide production-grade security guarantees.

The presence of this policy does not imply that every reported issue can be fixed or that a particular response or resolution time is guaranteed.

Thank you for helping keep Dev-Trace and its learning community responsible and secure.
